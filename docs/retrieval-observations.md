# Retrieval observations

The enrolled native-local context query publishes actual read observations through the existing route `observation_publication`, delivery proof and `metrics.jsonl`. It does not reserve a paid call or fabricate a `budget_claimed` event. Each actual query has an opaque read operation and a distinct attempt. The original route, logical task, session, authority epoch, scope/context and Git identity are frozen before work. A new active route cannot retag that capture.

This is the existing OS-owner local profile. It is not enterprise authentication, an exporter, a model result, an acceptance decision or proof that all actions were observed. Current source policy, component enablement, held source identities and the original route are checked before publication. A foreign session, root substitution, source/policy change or handoff refuses publication. Stored observations remain subject to the existing current local-owner read and final disclosure checks. Same-process private Python types are not a sandbox.

Each operation also carries one native-proved policy-input observation. Its closed `read_profile` value selects only the fixed stdout or one of six native-hook input sets; the value is data, not permission. One canonical selector binds ordered path identities and raw-byte hashes for the actual policy, managed manifest, selected module files and continuation configuration. The local reader requires native delivery proof before using that selector. Changed, missing, malformed, unsafe or ambiguous inputs hide the whole operation, its proof map and raw journal hash. The reader rechecks this cut immediately before disclosure. This is conservative current exact-byte local policy equivalence: restoring the exact inputs can restore local visibility. It is not a monotonic revocation history or the separate Factory principal/service-epoch authority from #162. At-rest retirement and remote copies require their own qualified retention/deletion contract.

Enrollment is explicit for the current owned route. Use its actual observed epoch and revision:

```sh
getzilla route --trace-enroll --expected-epoch EPOCH --expected-revision REVISION --json
getzilla context query --root "$PWD" --query 'exact_symbol' --format json
getzilla report --trace-operation OPERATION_ID --as-of UTC_CUTOFF --json
```

The context JSON includes `trace_operation_id` only when a capture was created, with status `pending_delivery`. This ID does not prove journal delivery. A failed capture reports `capture_unavailable`. The native function separately returns `trace_observation_delivered`; the report requires the existing delivery proofs before disclosure. An unenrolled query performs no diagnostic capture or publication. Disabling the context module still prevents retrieval itself.

The producer measures the actual access cut, graph-cache lookup, structural selection, lexical scoring, rank/context fusion and context assembly. Cache lookup measures lookup rather than index construction. Stage durations use monotonic time. Overall elapsed time is measured independently; reports do not add overlapping or parallel spans to invent wall time. Selected source/index/configuration identities, bounded candidate/context counts and outcome codes contain no raw query, task text, document, prompt, response, path or exception message. Even these opaque identities and aggregates are private metadata, not automatically safe to export.

Cache hit/miss, empty selection, failure, expired deadline and cancellation retain distinct outcomes. An absent semantic, reranking or inference stage is unsupported, not a synthetic successful span. Provider input/output usage, cached tokens, TTFT, CPU/GPU/RAM and export delivery remain unknown without their own actual producer. These records establish no token or cost savings.

The memory capture allows at most 20 spans. Excess phases increment the existing publication loss count. Existing limits remain: 64 pending route rows, 8192 bytes per row and the bounded journal. A publication lock waits at most 50 ms. Source/CAS preparation has a one-second cooperative deadline; the existing Git source probe retains its own bounded subprocess deadline and existing journal delivery retains its separate 50 ms window. These bounds do not claim a hard realtime end-to-end latency. Publication occurs after the access broker call finishes. An observation failure does not repeat, reverse or change a completed read. A partial journal, missing proof or dropped record stays a visible coverage gap; reports remain partial.

## Optional exporter design for issue #152

No exporter module or remote destination is activated by this source. Langfuse remains a compatibility/cost candidate. The following design is the input to a separately selected #166 adapter; it is not an implemented or qualified backend contract.

Use the existing optional-module registry and lifecycle. Install leaves the exporter disabled. Enablement must name the exact project, destination identity, fixed field allowlist, transformation policy/version and retention/deletion contract. Feature selection alone grants no data access or egress. Disabled or absent modules create no worker, buffer, model request or network call. Core remains usable without the module.

The adapter reads the existing canonical journal through current principal/project authority. It must retain the original task/run/attempt and complete service-owned source lineage. It uses #151 transformation and the existing native access/release broker before storage or disclosure. Caller strings, offline rows and a cached earlier allow cannot authenticate a principal, authorize fields or select a destination. Raw prompts, documents, answers, credentials and arbitrary exception strings stay excluded. Hashes, project names, links and aggregates require explicit field-purpose permission too.

Publication uses the existing result broker/outbox, not a second authoritative trace journal. Deduplication binds the original event identity, destination and contract revision. It must not repeat the original task, tool call or inference. Proposed adapter ceilings are 64 records and 256 KiB per batch, a two-second request deadline, and at most three confirmed-safe attempts; the canonical journal/outbox keeps its own stricter limits. An ambiguous remote result requires destination reconciliation, not a blind retry. Capacity loss and unavailable endpoints remain visible. These proposed exporter limits do not change local producer limits or claim implemented retry behavior.

Revocation is rechecked before each read and final release, including two distinct principals and projects. The registered backend must prove idempotent receipt/readback, authorized retention, derivative and exported-copy deletion, timeout/cancel cleanup, and rollback/disable behavior. If it cannot prove deletion or safe reconciliation, that profile remains unavailable. Existing local storage stays the source; remote acceptance cannot create work acceptance, route authority or a complete-coverage claim. Actual backend latency, storage/memory overhead, delivery, deletion and cross-principal qualification remain NOT_TESTED until that selected adapter is composed and exercised.
