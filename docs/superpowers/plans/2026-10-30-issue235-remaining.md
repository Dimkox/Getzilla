# Issue 235: remaining model continuation work

Status observed 2026-10-30. Automatic live model switching is not available. The six native clients are not qualified. This plan describes the remaining work; it does not grant permission to send data or change production systems.

## Existing evidence and dependencies

- The controlled Codex path runs two real local Docker containers with a separate fixture journal, a synthetic provider, a checked checkpoint and a stopped-container check. It does not use a real provider or establish live effect safety.
- PR #260 adds durable direct-model accounting and keeps dispatch disabled. Its local verification and independent reviews passed for `e1786a92579e79eefe23968a01c0654f6166156f`. It remains open until all required exact-head checks and review threads are resolved.
- PR #262 addresses architecture fitness secret-class matching from #261. It must preserve strict legacy behavior and pass its own exact-head review and checks. It does not establish permission to transfer data.
- Branch `feat/235-live-model-rotation` adds a separate synthetic model-rotation domain, terminal categories, shared budget and recovery checks. Synthetic outcomes cannot update the live journal. It depends on #260 and needs a fresh base, reviews and full gate before merge.
- Branch `feat/235-data-admission` contains an offline preview and opaque account-metadata resolver. They never assert consent or account ownership and cannot dispatch. Route `8694765ddcc0` has pending scope/design and external-write workflow gates. The branch depends on #260.

## Required implementation order

1. Finish the exact-head checks and review-thread resolution for #260 and #262. Rebase dependent branches on the actual merged main and repeat their independent reviews and verification. Keep old results tied to their original commits.
2. Define and implement data admission for the exact canonical payload bytes, recipient endpoint, provider, model, account, task, owner, route, source/checkpoint, policy revision, generation and expiry. The user must explicitly authorize the actual data and recipient. A caller boolean, an ordinary repository grant, a hash or a secret scanner is not proof of consent. Reject changed, stale, revoked or unverified data before a journal claim or network access. Never record raw prompts or credentials. Treat request digests as sensitive because low-entropy inputs can be guessed.
3. Bind each configured account to a credential handle and immutable version through a trusted provisioning source. Verify the actual provider organization/project/account with an authorized source; a matching `account_ref`, key format or caller-supplied label is insufficient. A changed handle, credential version, account or destination invalidates prior admission. Do not inspect other accounts or read secrets during development.
4. Connect admission and the request budget claim at one durable boundary. Count the original request and every retry before bytes leave. Recheck policy, destination, rate ceiling, deadline, credential version and authorization immediately before forwarding. Unknown pricing or an unverified token ceiling blocks dispatch. Operator estimates alone are not a provider-enforced spending cap. A lost response, timeout or crash after send remains unknown and cannot be resent automatically.
5. Implement provider-only egress under an OS-enforced boundary. The old executor must not bypass the host broker through direct sockets, DNS, alternate proxies, tools or mounted credentials. Bind the host transport to an approved provider/account/model and a fixed protocol and endpoint. Deny redirects and implicit retries unless they have separate authorization and budget. Do not equate a transport shutdown with reconciliation of external effects.
6. Connect a real coordinator to journal and owned execution lifecycle. Before switching, prove the old generation is stopped or fenced, preserve and verify the full task checkpoint and reconcile any started local or remote operations. A terminal event, interrupt acknowledgement or unchanged journal is not a process fence. If an effect or checkpoint is unknown, stop without replay. Never reset or overwrite user work to manufacture a clean checkpoint.
7. Implement and qualify adapters for Codex, Qwen, Claude, Gemini, Copilot and Grok on their supported native launch paths. Bind each event to its actual session, turn, generation and provider; classify confirmed model rate limit or technical failure only after native retries end. Authentication, billing, safety, tool failures, cancellation and unknown outcomes must not trigger a switch. Selection follows the configured candidate order, not price or task type.
8. Add local, non-paid end-to-end tests for every boundary and restart point: concurrent and duplicate claims, policy and credential revocation, altered payload and checkpoint, budget and deadline exhaustion, retry delays, process descendants, lost responses, unknown effects and container cleanup failures. Then qualify native client behavior and provider-specific account evidence with explicit owner authorization. Mock or synthetic-provider success is not live qualification.

## Recovery and release

Preserve journals, checkpoints and ambiguous outcomes for investigation. Disabling the policy stops new admission; it does not erase prior charges or resolve pending effects. Deliver each source change through its own reviewed PR. Require exact-head local verification, the repository's required external checks, resolved review threads and any separately required human-signed security approvals. Do not fabricate approvals or use a local receipt as merge authority.
