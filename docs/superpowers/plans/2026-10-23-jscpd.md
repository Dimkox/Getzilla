# jscpd integration implementation plan

Goal: add optional source-only duplicate analysis and the pinned updater component.
Design: [source duplication contract](../../jscpd.md). Use the existing Python CLI,
toolchain, installer and injected updater runner. No new service or framework.

Chosen approach: snapshot source and run installed jscpd 4.0.5 with fixed options.
Direct project scanning can load project config. npx can install during analysis.
Both alternatives conflict with the owner scope. Analysis remains offline.
The owner delegated implementation choices and excluded docs from scan input.

- [x] Add failing scanner and updater tests in tests/test_duplicates.py.
- [x] Add bounded source analysis and its CLI wrapper.
- [x] Add exact updater pin, default/selective dispatch and offline skip.
- [x] Bind optional tool advice, CLI dispatch and installed payload.
- [x] Run focused tests and actual pinned-tool detection smoke.
- [ ] Commit source and reconcile the review plan.
- [ ] Run architecture/governance and bounded committed-HEAD controls.
- [ ] Return exact source to independent reviewers. The coordinator runs the
  final full PR gate after independent review.

Review focus: source symlinks and escapes; malformed or oversized JSON; invalid
spans or missing tokens; unavailable or unsupported tool; offline updater.
No dry-run flag is added. Injected runners cover update mutation contracts.
Actual tool smoke is required before claiming measured duplicate detection.

Process ruling: pinned delivery commands use ignored runtime packages. Keep
workflow evidence there and durable product behavior here. Full PR verification
remains required for runtime, updater and packaging changes.
