# Limited managed command budgets

Issue [#153](https://github.com/Dimkox/Getzilla/issues/153) needs task and route token, compute and time limits, loop stops, escalation and observed cost per accepted PR. This implementation supplies one opt-in local consumer. It does not complete that issue.

`python3 scripts/getzilla_task_budget.py init` creates a budget in the current canonical route. Set `--calls`, `--failures`, `--repeat-failures`, `--elapsed-ms` and an absolute `--deadline-epoch`. Bind the real owner with `GETZILLA_SESSION_ID`. `show` returns charged and observed usage. `run --operation-id ID --timeout SECONDS -- PROGRAM ARG...` checks ordinary repository policy, reserves before the effect, claims once and starts a POSIX process group. Timeout is finite and at most 60 seconds. Output is discarded. This is a managed command path, not a shell or OS sandbox.

Limits and bounded operation records live in the existing canonical route, with the existing task lock, durable update and CAS. No new task, spend ledger, approval, price registry or supervisor is created. The public runtime methods require the exact logical task, current owner epoch and state revision. Initialization cannot replace limits or clear spend. Ordinary continuation, a source commit, a new agent and a native owner handoff retain the projection. Existing continuity refuses workspace relocation; copying a checkout does not authorize a fresh budget for an existing task. A separately requested new logical task has a distinct budget.

Reservations carry upper bounds for tokens, CPU milliseconds, cost in integer micro-units and elapsed milliseconds. A capped dimension requires a known bound. Unknown actual usage retains its reservation, and reports unknown observation. Actual usage above a reservation or cap latches a stop. Missing, invalid, oversized or unavailable state denies. The 256-operation storage ceiling never evicts spend. Failure and repeated failed-command limits stop later effects. A changed source, agent, epoch or operation ID cannot refill them.

The local consumer can enforce calls, failed attempts, repeated failed commands, absolute deadline and command elapsed time. It cannot measure or bound opaque child tokens, money or CPU. It always supplies `null` for those dimensions and refuses a mandatory cap on them. Caller-authored token or price claims are not used by the consumer. Generic reservation methods are for a future qualified adapter; their presence establishes no provider coverage. Other tools, `par`, native model clients, remote effects and other operating systems are not intercepted.

The claim and spawn share a short authority fence. The lock is released while the process runs. The consumer polls the original canonical owner, epoch and task status. Withdrawal kills the owned process group and reaps the direct child. `waitid(WNOWAIT)` keeps its PID pinned until signaling ends. A platform without that capability refuses execution. This does not contain a process that escapes its group or prove the reaping of arbitrary grandchildren; those require the separate process-guardian work. Cancellation is cooperative polling and bounded command timeout, not real-time preemption.

A lost outcome, crash, withdrawn owner or failed final publication leaves an unresolved reservation. Further effects stop. Replays never re-run a running or settled effect. A new owner cannot claim an old owner's reserved effect. Reconciliation requires a trusted adapter observation under fresh current authority; there is no CLI that accepts a user-authored success record. Review the original operation and actual surviving processes before a separately designed reconciliation procedure. A stop does not grant a budget increase, human approval, paid-run approval or external authority. The first paid-run gate remains unchanged.

Budget records store hashes, fixed outcome codes, counters and limits. They do not store commands, stdout, prompts, environment values, credentials or raw failure messages. They remain with the canonical task record; no automatic spend expiration or deletion is added. Existing task access, retention and lifecycle controls apply. These local records are workflow evidence and can be changed by a user who controls the filesystem.

`accepted_pr_cost` and `accepted_pr_count` remain `null`. A valid cost per accepted PR needs observed accepted outcomes, task-to-PR attribution, complete actual usage, official prices and human work observations. Issue #200 owns those empirical denominators. Local process timing does not establish financial ROI or defect-detection quality. Issue #138 still needs actual control overhead and accepted-change measurements.

Keep #150 access authority, #152 safe tracing and #156 tool/model capability controls separate from spend. No budget permits an effect denied by those controls. Roll out by explicitly initializing one offline task, running its managed commands and checking coverage and stops. Rollback removes the consumer integration while preserving canonical spend and unresolved effects. Do not delete the projection to resume a stopped task.
