# Local bundle feedback and optional GitHub observation

`trust-ci/scripts/check_security_bundle.py` checks explicit local evidence consistency without an App, account, remote model or database service. Its local source is `{"mode":"local","candidate_digest":"<SHA256>"}` with optional genuine Git head/tree. No GitHub IDs, PR, remote or workflow are required. The digest covers the canonical sorted path/mode/size/SHA256 source manifest. Existing Core execution is unchanged.

The CLI requires `--bundle`, `--policy`, and `--source-root`; pass an explicit `--snapshot-root` and `--input-descriptors` for source evidence. Optional `--observations` declares expected bindings only. There is no `--facts` option. The entrypoint constructs facts by reading the actual source and frozen inputs with the current accepted validators. A status claim in JSON cannot substitute for that work. Missing validators, source bytes or applicable evidence cause refusal.

The bundle contains a versioned tagged source, policy digest, normalized report/check records, optional independent binding and integration. `input-descriptors` contains the full check records and exact source ID inventory. `report.evidence_sha256` binds their entire canonical bytes. The boundary independently rederives applicability, inventory, source descriptors and the normalized report. It preserves accepted policy and per-source validation. Applicable non-OSV qualification remains unsupported in this component and refuses; no feed is acquired. A local consistency result does **not** say a scanner ran. Output always says `external_eligible=false`, `independent_attestation=false`, and `checks_executed_by_cli=[]`.

The pure evaluator accepts immutable normalized facts and an aware clock. It has no I/O callback. Facts and caller JSON are data, not authentication. An optional protected host must obtain its own fresh GitHub observations and validate its own source bytes before reevaluation. Its `public_admission.evaluate` compatibility function shape does not accept a local decision as authority. The new binding wire contract is versioned; historical prototype wire payloads are not silently upgraded.

Controls: bundle2MiB, other JSON1MiB each and6MiB aggregate; source bytes separately32MiB; snapshot raw/expanded bytes separately32MiB, member16MiB. Parser limits are depth24,32768 nodes,4096 members/container,4096-character strings,64 checks,128 sources,100 jobs. Output is64KiB. Original acquisition age is inclusive259200seconds. Missing, future, stale, duplicate, contradictory or unsupported evidence refuses.

GitHub observation uses at most14 GETs in20seconds, including final latest-workflow/PR/run reads,5seconds/request, raw response1MiB and aggregate4MiB. The complete initial latest-list entry replaces a redundant run GET; attempt, suite, jobs, workflow and blob checks remain. Run paths admit the exact bare workflow or its exact pinned branch/SHA suffix; workflow endpoint and blob paths remain bare. See the [GitHub workflow-run response](https://docs.github.com/en/enterprise-cloud@latest/rest/actions/workflow-runs?apiVersion=2026-03-10).

Each optional GET runs in an explicit owned one-shot process so DNS and buffered urllib reads cannot escape the parent's absolute deadline. Bounded nonblocking IPC shares that deadline and reserves cleanup time; timeout/overflow refuses, kills the unreaped owned group and reaps it. Cleanup uncertainty refuses rather than claiming completion. This is bounded process supervision, not a hard realtime scheduling guarantee. No worker is created by the local engine/CLI. Bounds apply before JSON; compression, redirects, foreign origins, effects and incomplete job pages are refused. No actual HTTP or App qualification is inferred from synthetic controls.

Snapshot preflight recognizes ZIP content even in extensionless authoritative hash objects. Raw and aggregate expanded sources remain32MiB, each archive member16MiB, with at most10000 members; it does not extract them or change original acquisition times.
