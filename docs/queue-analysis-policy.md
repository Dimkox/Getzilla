## Queue depth context v1

Adapter depth failures keep the exact existing `ArchitectureError` class,
message, arguments and `limit` code. The live, cached-height and declaration
checks retain their order and depth8 predicates. Diagnostics do not alter
classification, cycle precedence, demand/cache keys, source footprints or
resource charges. A real ninth level still refuses analysis.

At those three checks, a private frozen value captures the actual boundary,
base/head side, attempted module, active count and sorted active-module **set**,
attempted depth and limit. Cached reuse also records the actual cached height
and cached module **footprint** with its count. Neither set proves an ordered
chain, parent edges or the complete dependency graph. No further source read
or resolution takes place to produce the diagnostic.

The private provenance tuple retains all seven old positional fields and
appends defaulted `depth_contexts=()` and `depth_contexts_omitted=0`. The limit
catch accepts only the engine's exact private context type with its internal
marker and closed valid fields. This marker is an internal integrity check,
not a signature or protection against arbitrary same-process modification.
Generic errors with the same message do not supply measured context.

Every old limit tuple and finding remains exact. Separate advisory findings
start with `queue depth context v1: ` followed by canonical compact JSON.
Keys include `version`, `boundary`, `side`, `importer`, `attempted_module`,
`active_count`, `active_modules`, `attempted_depth`, `limit`, `cached_height`,
`cached_count`, `cached_modules`, `redacted`, `truncated` and `unavailable`.
Cached fields are null/empty outside the cache boundary. Both existing result
serializers retain string findings. These findings participate in the current
evidence digest; a historical digest does not become current qualification.

Identifiers must be whole dotted ASCII tokens of at most96 characters.
Invalid, long, Unicode, control-bearing and non-string values become fixed
`<unavailable>` markers with explicit flags; an apparent valid prefix is never
published. At most8 active and64 cached names are inspected/sorted. Overflow
omits that collection and retains its actual count and truncation flag.
Unknown scalars are null with an unavailable flag. No source bodies, requested
values, absolute paths, environment values or raw exception objects are emitted.

An encoded advisory is at most8192 ASCII bytes. A size fallback drops only the
advisory collections, retaining counts and a truncation flag. At most64 contexts
are retained per report in the existing deterministic source evaluation order;
additional contexts produce a bounded `queue depth contexts omitted v1: N`
note. Rendering sorts and deduplicates findings. These bounds never trim legacy
failures or source coverage. Optional diagnostic failure preserves the original
refusal; process interrupts retain their identity. Diagnostics supply neither
queue proof nor a new applicability input. They do not clear the twelve retained
PR393 depth refusals or establish the cause of any previous runtime timeout.


## Getzilla self-analysis profile (owner-approved November19)

The ordinary consumer profile remains64 unique source paths and2MiB aggregate
Python source. The explicit owner-approved Getzilla self profile permits128
unique source paths and4MiB. A129th path or one byte above4MiB refuses. This is
a resource policy, not queue identity, safe-callable proof or admission.

Only the fixed source-owned `architecture/queue-analysis-profile.json` selector
can request `getzilla-self-v1`. Its exact reviewed bytes must match the loaded
engine policy. A held, no-replace Git operation must prove the immutable
Getzilla source anchor `e99548d7cefca730cfad63c2f8cea1afe67bacd8` is an ancestor
of the current invocation HEAD. This current source-owned invocation profile
covers both head and historical base inputs; each exact input revision remains
separately bound. Historical input metadata does not select capacity.
Missing current policy selects the ordinary profile;
present mismatched policy, unknown lineage or changed custody refuses.
Copied consumer metadata cannot select a larger budget. Neither environment
variables nor caller-supplied numeric limits select a profile.

Profile identity includes the policy digest, project path, side and exact
revision. Resolution demands and transitive resource footprints retain that
identity. Self-profile cache results cannot enter an ordinary profile or another
project/side. Immutable source-only AST caches remain profile-independent;
every use still charges the current profile's complete source footprint.

Depth8, aggregate AST400000, logical work4096, individual AST200000, source roots64,
individual file limits, reflection/unknown rules, source custody, cancellation
and diagnostic privacy limits remain unchanged. Native scope seals are unchanged.
Exact selector code and policy bytes participate in verification source binding.
A bounded Git metadata frame counts each actual tree-entry header plus path bytes;
the existing absolute Git output ceiling and analyzed-file limit remain unchanged.

Current qualifying cold/warm resource observations belong to the exact clean
candidate's ignored runtime evidence. Earlier expanded diagnostic runs remain
nonqualifying and are never relabelled as profile acceptance. The final full
architecture and verification gates still cover the composed source candidate.
