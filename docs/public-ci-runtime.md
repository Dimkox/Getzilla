# Public admission API and worker (default off)

The existing API and worker have an explicit public mode. The private Trust CI pipeline remains the default. Public mode uses the single canonical public admission evaluator; a legacy green result cannot substitute for it. No App, workflow, image, machine signer or operator acceptance is activated by installing this code.

## Protected configuration and distribution

Pass both `--enable-public` and `--public-config /absolute/operator/public.json` to the API/worker. Initialize the journal explicitly with `adaptive-trust-ci public-journal-init --public-config ...`. This extends the existing journal without erasing deliveries, publications, nonces or pending operations. A changed scope refuses an old journal; it never resets it. API uses `TRUST_CI_WEBHOOK_SECRET` (at least32bytes), `TRUST_CI_READ_TOKEN` and the existing kill-switch path. ContainerExecutor retains network=none and receives no model/App/machine key.

The closed JSON configuration has `schema_version:1`, `publisher`, `authority`, `producer_key_path`, `app_key_path`, `journal_path`, `input_root` and `producer`. Publisher/Authority retain their existing exact repository, App/installation, source/tree/workflow/policy pin and required-job fields. Authority cannot supply Python objects or a security_core; its public key comes from producer_key_path. Paths are absolute. Configuration, keys and journal must stay outside candidate input_root and qualified snapshots. Config/public-key files must satisfy the existing owned single-link reader; private key files additionally require no group/other access. Use the runtime UID10001 in the shipped worker image.

`producer` contains `snapshot_root`, `machine_key_path`, `image_artifacts` (an explicit selected catalog path inside snapshots, or null), `cgroup_root`, and `dispatch`. Missing/unsupported image inputs stay blocked. App and machine keys stay on the host, outside candidate and snapshot roots. The machine key is a separately configured Ed25519 producer key matching producer_key_path. It signs only the canonical machine-binding kind; it does not create a human merge approval.

Dispatch is off with exactly `{"enabled":false}`. Enabling it requires exactly `enabled:true`, `app_id`, `installation_id`, and `key_path`. This is a separate runner-repository Actions-write role: its token requests only Actions write and Contents read for that one repository. Automatic dispatch requires Authority.event=workflow_dispatch. Repository_dispatch observation remains supported with automatic dispatch disabled. Read observation keeps Actions/Checks read; publication keeps Checks write for the target repository. Source installation grants none of these real App permissions. App installation/configuration and the first accepted image/checker/runner/workflow pins remain operator decisions.

The existing worker Dockerfile accepts all three build arguments together: `PUBLIC_CHECKER_REPOSITORY`, `PUBLIC_CHECKER_COMMIT`, `PUBLIC_CHECKER_TREE`. With no pins it builds the original private image. The build helper independently fetches that exact configured checker commit, verifies its genuine Git commit/tree and clean source, and tests module imports without running inventory/scanners. It installs the entire checker/configuration at `/opt/getzilla-checker`, retaining root-owned source and Git metadata. Only that exact path is trusted by Git's system safe.directory; the engine also uses exact per-command trust. There is no wildcard trust or writable candidate module fallback. Runtime verifies the configured checker pin before imports; source_binding sees this actual Git root, not site-packages. First pin acceptance is not inferred from a successful build. The explicit public build also needs `PUBLIC_CHECKER_INPUTS`: a context-relative directory containing real `checker-requirements.lock` and `wheels/`. The exact-hash lock must include the accepted Bandit pin, PyYAML and all dependencies. Installation is offline, wheel-only and hash-required. Missing tools fail the build; the checked-in README is not a qualified wheelhouse. The private image with no checker pins needs none of these packages.

## Autonomous producer flow

An authenticated PR webhook is only a wakeup. The worker first tries the current canonical producer result. If it is unavailable, the default-off dispatcher independently checks the open PR, pinned runner branch/workflow/blob and current run state. It records durable intent before token issuance/POST and requests the shipped `getzilla-public-producer.yml` workflow with only a PR number. The key includes actual source, scope and selected snapshot bytes. Identical failed/missing inputs do not create an automatic dispatch loop. A pending or unknown dispatch cannot be re-posted. Existing running/UNKNOWN publication state fences all refresh and dispatch, including after restart.

The shipped workflow runs on a dedicated trusted `getzilla-public-producer` self-hosted control runner. It uses an explicitly configured immutable `PUBLIC_PRODUCER_IMAGE` repository digest, without checking out or executing candidate commands. The container has only its read-only GitHub job token, protected config/public producer key, qualified snapshots and owned work storage. App and machine private keys are not mounted. Its `public-prepare` entry independently matches the running workflow/run/attempt/runner SHA to provider data, obtains the current candidate as Git data, executes the installed pinned checker against explicit qualified snapshots, and seals an unsigned preparation only after full canonical input/coverage validation. No failed/missing evidence yields success.

The workflow must be installed and independently pinned in the configured runner repository. The required job name is `public-security-producer`. The fixed workflow mount paths are `/etc/adaptive-trust-ci/public.json`, `/etc/adaptive-trust-ci/producer.pub`, `/var/lib/adaptive-trust-ci/public-inputs`, and `/var/lib/adaptive-trust-ci/public-snapshots`. Configuration must name these same container paths. Registration of the dedicated runner, actual image digest and its protected data/delegation mounts are bootstrap configuration; no custom host Python or manual per-PR record drops are required. The service can dispatch this workflow only after its explicit Actions-write role is configured. No workflow is dispatched by author tests.

After GitHub reports the producer run completed successfully, the HMAC-authenticated completion webhook wakes known blocked PRs even when the runner repository differs or its PR array is empty. The host refresh consumes the generated preparation, rechecks exact source/snapshots, canonical coverage and current provider identities, then stops its entire delegated group and confirms it is empty before the separate fixed machine signer runs. The signer denies process/network effects. It rejects other payload kinds and expired payloads. The host verifies the signature and unchanged source/snapshots before sealing the record. The current canonical publisher still independently revalidates it before any external check write.

An original cached signature is reused only through canonical currentness/expiry validation. Its creation time/run/attempt never become new execution credit. There is no refresh after an unresolved effect. UNKNOWN retains the same in-memory allocation/nonce; running/unknown durable rows and pending/unknown dispatches refuse a fresh allocation after restart. Unfinished source/signing generations are not overwritten. Recovery requires separately qualified quiescence; no lease expiry guesses success.

## Bounds and refusal

The supported source profile covers the measured accepted Getzilla tree:64MiB/8192 files. It retains every selected source file and fetches needed Git ancestry without shallow pruning. Source graph sizes are checked before checkout, then actual file bytes and identities are revalidated. The separate Git store is bounded to64MiB; source plus Git/control storage is bounded to two source allocations plus the existing6MiB control allowance. Polling detects storage exhaustion; physical transient disk peaks are not claimed to be a qualified filesystem quota. A source history exceeding this profile refuses; it is not silently truncated. Snapshots remain32MiB/4096 files; envelope2MiB, member16MiB and existing snapshot archive bounds are unchanged. All analyzer/API limits stay unchanged.

Each producer worker keeps an original20s deadline. HTTP keeps the existing5s request,1MiB raw body,4MiB shared allocation and request counters. Tokens/dispatches consume that same bounded operation budget; no ordinary transport callback is used. Dispatcher responses must be204 with an empty body. Unexpected/failed outcomes stay unknown. Webhooks remain5s/1MiB. Wakeups plus dispatch intents share4096 retained records; capacity refusal does not evict history. Closed producer step logs rotate at2048bytes with one2048byte backup and never include raw errors, keys or advisory values.

The Linux producer profile requires a real delegated cgroupv2 domain with the pids controller enabled. Each owned generation receives pids.max128. The fixed child is attached and its membership read back before work is sent. Cleanup uses the held cgroup.kill/events/procs descriptors, confirms the whole group empty even across nested sessions, closes descriptors and removes only that owned leaf. Missing delegation, unsupported kernel, failed membership or uncertain cleanup refuses. Cleanup uncertainty becomes durable UNKNOWN; it cannot start another refresh. These controls do not prove confinement against arbitrary processes that can move themselves into another delegated group.

Use the shipped `trust-ci/ops/public-worker-cgroup.conf` as a drop-in for the existing dedicated control/worker unit (systemd254+), not as an automatically installed service. The delegated parent must be owned by the runtime UID and not group/other writable, have pids in cgroup.subtree_control, and keep the supervisor in its own leaf. Bind that actual delegated parent at configured cgroup_root (the workflow uses `/sys/fs/cgroup/getzilla-public`). The workflow's host cgroup namespace exposes only the separately delegated writable mount; operator qualification of this topology remains required. Run `adaptive-trust-ci public-preflight --public-config ...` only during authorized operator setup. It measures an empty owned group and grants no external eligibility. No cgroup or service setup is performed automatically by installation.

Canonical GitHub admission independently reruns the pinned accepted full-family evaluator against the explicit snapshots, compares every structured result/coverage, and preserves all raw evidence. Positive license/EPSS evidence records are retained and counted separately from refusal findings. The read-only local CLI retains its original no-execution feedback profile. The accepted checker currently lacks an independent-run OCI evaluation contract: prepare_inputs/evaluate have no image_artifacts interface at a514, input_profile binds run.head_sha to candidate head rather than the real independent runner head, and scan_images uses the legacy Docker source. Applicable images therefore have a specific missing accepted implementation and remain refused before daemon access. They cannot be closed with configuration or pasted markers; an independently accepted source/run-aware offline image evaluator is required. Genuine images, licenses, holdout and checker bootstrap remain real dependencies. Source controls/builds do not constitute public #326 rollout, human approval, atomic merge-backend acceptance or production qualification. Public job readback and health readiness grant no merge authority.
