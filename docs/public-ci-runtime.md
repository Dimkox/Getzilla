# Public admission API and worker (default off)

This is a default-off staged-input host adapter for the existing canonical security-bundle verifier and public check publisher. It does not yet provide autonomous evidence acquisition. The default `adaptive-trust-ci api` and `worker` retain the private Trust CI job pipeline. A legacy job's green check is never substituted for canonical public admission.

Public mode requires both `--enable-public` and `--public-config /absolute/operator/public.json`. Supplying only one refuses startup. The configuration and journal belong to the protected operator host, outside candidate checkouts; API and worker must see the same configuration/journal. No repository workflow or CI runner receives the App private key or a model key. ContainerExecutor network isolation is unchanged.

Prepare the journal explicitly with `adaptive-trust-ci public-journal-init --public-config /absolute/operator/public.json`. This adds its wakeup schema without erasing existing publications, delivery IDs, operation nonces or pending mutations. A changed configuration scope refuses the old journal rather than resetting it.

Start the existing API and worker commands with both public flags. API uses `TRUST_CI_WEBHOOK_SECRET` (at least32bytes), `TRUST_CI_READ_TOKEN` and the existing `TRUST_CI_KILL_SWITCH_PATH`. Public worker needs none of the private CI database/holdout/signing-key settings. All actual operator IDs, keys, producer/checker pins and source inputs must be supplied; no example value is evidence or authority.

The closed configuration object has `schema_version:1`, `publisher`, `authority`, `producer_key_path`, `app_key_path`, `journal_path`, and `input_root`. All paths are explicit absolute host paths. `publisher` is the existing PublisherConfig: repository (full name), repository_id, independent app_id/installation_id and policy_digest. `authority` supplies the existing canonical Authority fields except `public_key_pem` and `security_core`; required_jobs is a nonempty JSON list. SHA pins are exact40-hex, policy is64-hex. Configuration, both key paths and journal must stay outside input_root. The App key is an owned, single-link regular file with no group/other access and at most64KiB. The producer public key is read from producer_key_path; the App RSA private key is read only inside the fixed bounded credential worker. The security core is selected by the trusted installed checker, never the candidate or webhook.

The current adapter consumes `input_root/<pr>/record.json` containing exactly `selector` and `evidence` in the existing canonical formats, plus the bound read-only Git source at `candidate/` and sealed hash-named input objects at `snapshots/`. These are declarations until the canonical evaluator independently checks current source, producer/run/attempt, signatures, full coverage, snapshots, policy, freshness and lifetime. Missing images, licenses, checker bootstrap or holdout remain refusals. No shipped workflow or refresh command produces this staged record, candidate checkout and snapshot set from GitHub. Manual per-PR file drops are an integration dependency, not autonomous operation. The missing independent producer must export the signed canonical binding, report, complete snapshots and source/integration identities for the pinned workflow/run/attempt; webhook data cannot replace them.

The existing `trust-ci/Dockerfile.worker` installs only the Trust CI package. It does not ship the repository-relative `.getzilla` validator tree required by canonical `public_admission._core()`. Public publication in that image therefore refuses with an unavailable checker. A separately qualified accepted-checker distribution with its pinned source/configuration and runtime dependencies is still required; candidate code or custom host Python must not supply it. No working public worker image or accepted checker bootstrap is claimed here.

The webhook is a bounded5s/1MiB wakeup. pull_request, workflow_run and check_run can select PR numbers only when their payload names target-repository PRs; cross-repository producer completions or empty PR arrays do not refresh inputs or trigger a retry; body evidence/authority claims are ignored. Durable delivery dedupe and a4096-record queue refuse capacity exhaustion without evicting history. API job readback is `/public/jobs/{job_id}` with the read bearer. Health readiness proves local ingress/journal availability only. The additive machine interface is `engineering/contracts/openapi/trust-ci.public.v1.json`; the private contract remains unchanged.

HTTP uses a fixed owned child: TLS verification, no proxy/redirect/compression, original5s absolute request boundary (including blocking DNS),1MiB raw response bodies,64KiB input framing, and the original shared4MiB allocation. Header parsing has an additional64×1024-byte profile. Read observation gets a read-only App token; checks-write minting happens only when the canonical publisher requests it after admission. Both token requests per mint consume the same16-publication-request/raw-byte budget. There is no ordinary transport/token-callback fallback.

UNKNOWN keeps the same in-memory verifier/allocation/nonce and prevents a different PR from creating another unresolved allocation in that worker. Interrupted/running durable jobs are not automatically reclaimed or replayed. A restart cannot reconstruct trusted allocation authority from journal JSON; unresolved operations require separately qualified operator recovery. Publication readback does not grant merge authority. The independent atomic merge backend, human owner approval, real App setup/protection and operator/runtime acceptance remain OPEN; this code does not configure or activate them.
