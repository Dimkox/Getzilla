# Release and delivery plan

Deliver the combined source through an isolated pull request. Preserve published v2.2.1 identities. VERSION 2.2.2 is a source candidate, not a published release.

Before transport, complete source repairs and committed bounded controls, then selected independent code, test, security and release reviews. Persist their complete reports and freeze. Run one final qualifying local PR gate and require configured external checks on the exact PR head. Resolve every review thread. Materialize exact delegated actions; merge with --match-head-commit, never --admin. Tag and publish only the merged tested commit.

No agent workflow dispatch, direct protected-branch push, deployed policy change or paid provider call is part of this delivery. Local evidence does not replace external authority.

Production deployment needs an exact target, operation and acceptance scenario from the owner. The target is not established. Native host control loading, allow/deny-before-effect audit, shared-host paid enforcement, process credential removal and provider revocation remain separate acceptance work. Do not close their issues from source tests.

Observable signals: denial reason and policy identity; installed versus loaded and host-verified status; durable reservation state and scheduler/task attribution without secrets; frozen lock/profile drift checks; exact-head CI result. Unknown spend keeps its reservation. Fail closed on missing controls or admission.
