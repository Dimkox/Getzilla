# Local Factory source access

This first slice reads registered owned local files and sends their sanitized text to a registered UDS. It uses the existing private actor authority, durable execution packet, lease and result outbox. It does not qualify Core hooks, general file/search/shell/MCP tools, model-generated lineage, remote connectors or OS isolation. Those remain required for the full trusted-access contour.

Protected access defaults to unavailable. Existing V1 actor files and ordinary APIs retain their behavior. V1 credentials cannot open the protected source channel. The server's trusted parent can explicitly supply a `LocalSourceAdapter` and a destination map of actual `UdsResultHandoffClient` instances to `build_app` or `main`. Requests cannot register paths, transports, callbacks or destinations. Each client must use an actual checked UDS and a timeout at most two seconds. The server co-composes one authority instance and its existing `ResultDispatcher`; a separate ordinary dispatcher cannot recover protected permissions from the database.

The existing `actors_file` supports a closed V2 document with `schema_version: 2`, positive CAS `revision`, `actors`, `groups`, `sources` and `destinations`. Each actor retains `actor_id`, `kind`, `scopes`, `repositories` and `token_file`; it explicitly adds `credential_generation`, `principal_id`, `tenant_id`, project/repository pairs, and a credential delegation owner/expiry. This credential narrowing does not replace the task packet or lease. Workers require an owner and expiry. Principals and owners must exist in the same operator snapshot. V2 bounds are 256 actors, 256 flat groups, 4096 source restrictions and 256 destinations in at most 1 MiB. Unsupported inheritance and connector permission models have no protected adapter.

A source key contains tenant, project, provider, site and resource. The first adapter accepts only provider `local`. Server registration binds that key to repository, workspace handle, a relative packet path, file location, version and exact content digest. Files must be owned regular mode-0600 single-link files under trusted ancestry. Descriptor checks precede reads. The durable packet must allow `read_file` and the registered relative path; a broad credential cannot widen it. A request can select at most 128 distinct keys. The service reads at most 256 KiB, intersected with the packet output limit, and applies the existing text sanitizer. It creates immutable bytes and complete lineage itself. General caller/model payloads and claimed dependencies are not accepted.

`POST /v1/access/source-read` takes the existing lease grant, execution packet digest, source selectors and a registered destination ID. It returns only an opaque prepared ID. `POST /v1/access/release` consumes that ID once for the same authenticated credential generation. The actual destination policy supplies its tenant/project/repository and audience. Every recipient must currently have source access. A private source cannot be relabeled public. Prepared state expires after two seconds and is never restored from JSON, events, checkpoints or outbox rows.

The optional operator mutation endpoint `POST /v1/access/authority` requires an authenticated operator with explicit `factory:access-admin`, which is absent by default. It accepts only an expected revision and the closed replacement authority. It validates private credential custody, atomically replaces and fsyncs the existing file, then publishes the new immutable pointer. Successful pointer publication is t0. Unmanaged file drift or an uncertain replacement disables protected operations. Credential rotation requires a strictly greater credential generation. Permission digests exclude credential values, credential file references and credential generations; the separate current snapshot/session checks enforce those freshness dimensions.

Migration 027 extends the existing 024/025 outbox with owned lineage/transform/destination/authority facts and single-use phase. Migration 026 is the exact local stop-revision dependency from `e73d87e111e59dd893184b7284027eee820bfcb7`, not an accepted main dependency. Protected rows retain `dispatch_phase=blocked`, so ordinary polling/reconciliation cannot send or repost them. Unknown outcomes retain their existing operation ID and require observation; they do not create another send attempt.

Admission locks and rechecks the actual task, execution packet, attempt and existing stop revision. The short SOURCE mutex performs only bounded native memory checks and pending queue publication. It contains no SQL, file operation or transport callback. The queue becomes ready only after a verified database commit. Rollback or unknown commit loses volatile permission. Dispatch repeats task/source/destination checks, verifies a separate commit, then releases all database and source locks before the actual UDS handoff. A source update after dispatch admission can have a late or unknown external effect. Already disclosed bytes cannot be recalled.

The initial queue holds at most 64 references and 16 per principal, with 250 ms admission expiry and batches of eight. A 50 ms poll plus immediate wakeup replaces the ordinary one-second poll for this profile. Source checks refuse when their measured processing exceeds 5 ms. SQL uses a 500 ms lock wait, 1500 ms statement timeout and 2 s transaction timeout; these are refusal bounds, not a hard real-time return guarantee across filesystem stalls or connection establishment. The current proof uses disposable PostgreSQL 17, generated credentials, owned files and a real local UDS. It makes no deployed-service, provider or native-client claim.
