# Getzilla delivery

Read the canonical route selected by the caller’s explicitly bound session and load its workflow skills. Use only selected agents. Keep exactly one writer per isolated task; review fixes return to that writer. Measure startup capacity before dispatch and bound concurrent workers to that capacity. Dispatch all independent selected analyses in one wave, then synthesize their findings before implementation. Give each analysis the route ID, canonical root, selected package, narrow question and runtime report destination.

The initial route is provisional. After committing source and before reviewer dispatch, run `python3 scripts/getzilla_route.py --reconcile --json`. The complete assessment binds the trusted comparison bases, HEAD/tree, rule digest and review plan. Each change has one ordinary code review covering correctness and test adequacy. Security, data and release audits require both a changed sensitivity category and risk threshold from the diff policy; prompt wording and repository domains do not select them. Incomplete source inventory blocks qualification. The final verifier rederives the plan and rejects stale evidence.

Retain explicitly selected additional reviews with `python3 scripts/getzilla_route.py --reconcile --add-reviewer test_reviewer --add-reviewer release_reviewer`. This only adds review obligations and their dispatch authority. Legacy routes retain their selected wave automatically. Operational gates, grants, writer and analysis authority remain separately bound.

## Unfinished task and scope

Bind the caller's real harness session with `GETZILLA_SESSION_ID` (which takes precedence over `CLAUDE_CODE_SESSION_ID`) or `getzilla_route.py --session SESSION`. `manual` and global discovery are read-only: they do not authorize worker start, grants, reconciliation or task completion. Read the selected canonical `routes/<route-id>.json`; `active-route.json` and session pointers are repairable projections, not independent authority. Use explicit `--continue ROUTE_ID --session SESSION` to select an owned task. Cross-session handoff additionally requires the observed `--expected-epoch N --expected-revision N --request-id ID`; retry the same request after a projection failure. Handoff refuses an active, interrupted or unreadable worker ledger and invalidates prior authority. Never invent a native child ID or interruption ACK.

An ordinary same-session prompt continues any unfinished task, including `ready`. Preserve the original task, stable `logical_task_id`, source/base and selected writer. Qualified follow-ups are ordered pending amendments; bare continue/status, empty input and system notices add nothing. Only explicit `--new-task TEXT` starts a fresh identity, even for identical text, and it refuses an open package or active worker. Close the existing package/task through their normal commands first. Stop never completes a ready task automatically.

Pending scope is bounded to 16 entries, 8192 UTF-8 bytes each and 65536 bytes total; a new original is bounded to 65536 bytes. Larger legacy originals remain intact. Equal text remains separate unless a trusted stable event ID proves exact replay. Overflow retains prior scope and a bounded NOT-admitted digest/byte-count latch; do not truncate, summarize away, evict or invent withdrawal. Resume context is task data, bounded to 16384 UTF-8 bytes with an omitted-byte count and canonical recovery path.

Before qualification, explicitly synchronize original and pending scope into the selected typed spec and requirements. `--ack-scope PATH` consumes a repository-relative closed JSON request binding route, logical task, authority epoch, context revision, spec digest, raw requirements digest and the exact item-to-typed-ID mapping. Only named pending items clear; a package-first interrupted transaction must be retried exactly. A rejected input requires its original bytes again and a valid incorporation mapping or an actual current user withdrawal. This records incorporation, not acceptance, approval or PASS. See `docs/REFERENCE.md#task-continuity-and-context-binding` for the request and API. Scope gaps remain failures on unchanged source.

## Light lane

A route with `delivery_lane: light` is provisional. The verifier admits it only from a complete, clean Git comparison: at most 50 added plus deleted code lines, excluding ordinary tests and non-executable Markdown/RST/text. It checks sensitive paths before these exclusions. Control files, hooks, runtime code, Trust CI, migrations, dependencies, locks and CI require the full lane. Binary, rename, submodule, unknown and incomplete inventories also require the full lane. Medium/high risk or a larger diff restores the full review floor.

For an admitted small change, keep scope and acceptance in the task or PR. Do not create a change package. Add a failing regression when behavior changes, implement the change, and run focused controls. Commit the source candidate and reconcile the route. Have one independent code reviewer inspect code and tests; configured or explicitly retained additional reviews still apply. Save the report to `.getzilla/runtime/reviews/<route-id>/code-review.md`. Run `python3 scripts/getzilla_verify.py --mode fast`; the measured selector must admit the change. A source repair needs a new committed candidate and fresh reviews. CI retains its full suite and exact-head merge gate.

`fast` selects the verifier's fast profile; it does not promise changed-test-only execution and can still run full test discovery. Explicit `--mode fast --no-record --test <module> --budget 180` is only a bounded observation, without a receipt or light-lane admission.

## Full lane

1. Run `python3 scripts/getzilla_change.py start` when the selected delivery requires a package. New packages live in `.getzilla/runtime/changes/<id>/` and are ignored by Git. Existing tracked packages remain readable history; commands copy them into runtime before new writes. PR/release verification needs the package and its typed spec except for measured light admission or the existing low-risk docs/micro exemption.
2. Record scope, acceptance, design, tests, rollout and rollback in the package. Dispatch independent selected analyses and save concise findings in `<package>/evidence/analysis-<agent>.md`. When a named human gate lacks approval, present the concrete decision and stop before its dependent action. Existing explicit owner decisions remain valid within their scope. Record the scoped/approved lifecycle transitions with `getzilla_change.py transition`; ordinary tasks with no named gate proceed after the bounded design.
3. The selected writer adds a failing test when behavior changes, implements the bounded change, and runs focused controls. Keep exact commands and outcomes in runtime evidence.
4. Commit the source candidate and reconcile its review plan. Dispatch all selected independent reviewers against that exact HEAD/tree. Reviewers return reports out-of-band and do not modify the candidate. Save reports in the runtime package evidence directory or `.getzilla/runtime/reviews/<route-id>/`.
5. Run one final `python3 scripts/getzilla_verify.py --mode pr`, or the existing focused landing mode when its closed inventory qualifies. Release work uses `--mode release`. PR/release may select the disclosed docs-state-focused profile only when its closed inventory qualifies. Do not shorten the comparison range. Record skips as skips. No report-only or workflow-state freeze commit is needed.
6. After the gate passes, record each passing report with `python3 scripts/getzilla_review.py <kind> --status pass --report <runtime-report> --reviewed-commit <exact-full-sha> --reviewed-context <observed-context-digest>`. Runtime reports must be ignored, regular, non-executable UTF-8 Markdown using the conventional review names. The report itself contains exactly one standalone `reviewed-context-digest: <64 lowercase hex>` line captured by the reviewer for the inspected scope. The matching CLI argument cannot relabel an old report. The receipt binds route/task/epoch, scope revision, package/spec/requirements, exact reviewed HEAD/tree and the hash of those same report bytes; consumption rechecks all bindings. A source commit, report edit, amendment, handoff or changed scope document requires fresh evidence.
7. Run `python3 scripts/getzilla_status.py`; completion requires zero evidence gaps. Runtime state may transition to ready without changing source. Deliver through a PR with the required external exact-head checks: GitHub Actions for public repositories, Trust CI for private repositories. Local evidence never replaces merge authority, branch protection or human security approvals.
8. Before you end the task, record every Getzilla defect you met (a bug, a wrong refusal, a broken check, a doc that does not match the code, costly friction), also the ones you worked around. Follow the "Getzilla defects" rule in `AGENTS.md`: an issue in `Dimkox/Getzilla` when that is allowed, otherwise a ready issue text for the owner.

## Evidence and handoff

Store state, startup snapshots, analyses, reviews and verification output outside Git. At most one concise summary may be tracked per change. Keep durable product contracts, canonical docs and source in Git. Export portable local evidence with `python3 scripts/getzilla_evidence.py --output .getzilla/runtime/exports/<change-id>.zip`; attach it separately to a PR or publish the concise findings in PR comments. The bounded archive contains source identities and hashes, never approval grants or keys. Importing an archive does not activate receipts.

Public CI exports its own actual run logs, startup snapshot, verification report when produced, state and exact source provenance. It retains artifacts for 30 days. A fresh runner does not have workstation analyses or reviews and labels them unavailable. Do not claim they were rerun or uploaded by CI.

Historical tracked review receipts retain their old report-only-delta validation. Do not rewrite historical evidence or pinned fixtures to adopt the new layout.

## Review and authority

Review security, duplicate external writes/idempotency and tests. Keep reports short. Mutation probes are required only for critical code: security checks, policy and permission parsers, authentication, money or external-write paths, and data deletion. For other changes state `mutation: skipped (non-critical)`. Require a clean committed candidate for every review; return dirty candidates to their writer. When probes apply, reproduce the exact reviewed commit in scratch with `getzilla cleanup snapshot <commit>`. The command copies committed content only, not staged, unstaged or untracked changes. Unsafe scratch, a mismatched snapshot or modified candidate makes the review inconclusive/stale. A failed check or finding returns to the selected writer. Run bounded, change-relevant probes in reviewer-owned private scratch under the canonical root's `.getzilla/runtime`, outside the reviewed candidate, with a trusted non-sticky parent and mode 0700. For every review, record exact reviewed HEAD/tree and tree fingerprint before and after, clean-source observations, `reviewed-tree-modified: no`, exact commands, outcomes and unexecuted claims, even when mutation is skipped. Inconclusive probes are not passes.

Every new grant binds the exact route, stable logical task, owner session and authority epoch, as well as its existing resource, source and TTL restrictions. Protected edit grants also bind exact files, branch, repository, change and anchor. Approved-file commits may retain a grant only within that same task and epoch; a new task or handoff rejects earlier grants for both old and new callers. Unbound discovery never consumes authority. Legacy grants remain usable only on a proven unchanged, unamended legacy task without handoff; never upgrade or copy an old record to current bindings. Production/external grants retain exact HEAD/tree binding and separate authority. Follow conditional AGENTS L5 for merge, tag and release; `getzilla_deploy.py` remains prepare-only without separate authorization. If review or verification cannot run, record NOT_RUN or BLOCKED and its reason. Never fabricate approvals, independent reports or successful receipts. An explicit owner override of a local rule records the rule, scope, reason, deferred checks and follow-up; label the result UNVERIFIED until those checks run. It never bypasses external exact-head checks, branch protection or human private-key authority.

After a tool denial, do not repeat it unchanged. One semantic correction is allowed. A second denial for the same objective is a blocker; report the named action and reason. Request a protected-path grant only for exact targets identified by the hook.

Reviewers return the complete report to the coordinator out-of-band. After all reviews finish, save reports outside Git and run one final qualifying gate. Use one canonical project root. Put private scratch outside the reviewed candidate and outside the reviewed worktree, beneath that root's `.getzilla/runtime`. Record HEAD and tree fingerprint before/after, scratch path, `reviewed-tree-modified: no`, exact commands and observed output. Report killed, survived and inconclusive mutants and all unexecuted claims. Read-only configuration is not an OS-enforced isolation boundary.

## Tool-denial circuit breaker

Never repeat an identical denied invocation. One semantic rewrite is allowed. If that also fails, report the blocked objective and stop dependent work. An opaque denial requires explicit targets before requesting a protected-path grant.
